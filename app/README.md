# Приложение (этап 3)

```bash
cd app
npm install
npm run dev        # http://localhost:5173
npm test           # 118 проверок
npm run build      # проверка типов + сборка + service worker
```

Браузерное приложение без сервера. Колода лежит статикой, прогресс — в
IndexedDB на устройстве, после первой загрузки всё работает офлайн.

## Устройство

| слой | где | зачем отделён |
|---|---|---|
| ядро повторений | `src/srs` | расписание и очередь, без React и без базы |
| хранилище | `src/storage` | IndexedDB через Dexie |
| ход занятия | `src/study` | что показано и что происходит по нажатию |
| экраны | `src/ui` | только вёрстка и события |

Ключевое здесь — что `src/study/controller.ts` **не часть интерфейса**.
React-компоненты подписываются на его состояние и пересылают нажатия, а вся
логика занятия живёт в нём. Причины две: это проверяется тестами без браузера
(16 проверок), и дизайн экрана мы будем переделывать не один раз — менять
вёрстку, не трогая логику, гораздо дешевле, чем выковыривать логику из
компонентов.

## Вёрстка временная

`src/ui` — скелет с правильной структурой, а не оформление. Ни цвета, ни ритма,
ни типографики, за которые стоило бы держаться: всё это будет заменено целиком.

Экран повторения имеет **три состояния**: пропуск скрыт, ответ раскрыт, очередь
пройдена. Плюс экран начала дня. Состояний было пять, пока был ввод ответа;
с самопроверкой «верно», «неверно» и «опечатка» исчезли — судит себя человек.

## Проверяет себя учащийся

Поля ввода нет. Система показывает пропуск, по требованию раскрывает карточку и
принимает оценку — как в Anki. Знание своего ответа есть только у того, кто
вспоминал; система может лишь угадывать по набранным буквам, и угадывает она
хуже.

Побочная польза: набор партнёров в кластере перестаёт быть проблемой. Подумал
`take`, увидел `make` — под ответом написано «так же подошло бы: take, reach»,
и засчитать себе верно ты можешь сам.

## Что уже работает

- Колода импортируется при первом запуске и обновляется при последующих.
  Нет сети, а колода уже в базе — это штатный офлайн, а не ошибка.
- Пробел или `Enter` раскрывает карточку, следующее нажатие ставит «хорошо».
  Оценки цифрами `1`–`4`.
- На кнопках видны сроки следующего показа до того, как выбрал.
- Подсказка по требованию.
- Заметка об употреблении и остальные партнёры кластера после раскрытия.
- Завал на экране дня — только когда он есть.
- PWA: манифест, service worker, колода в офлайн-кэше.

## Одно нажатие — одно действие

Разбор клавиш вынесен в чистую функцию `keyAction`, а обработчик вешается
**один раз** за занятие и спрашивает состояние сам. Это не украшение, а
исправление настоящей ошибки: если перевешивать обработчик при каждой смене
состояния, одно нажатие Enter успевает раскрыть карточку и тут же её оценить.
React перерисовывает экран внутри того же события, а обработчик, добавленный на
цель, до которой событие ещё не дошло, по спецификации DOM всё равно
срабатывает — карточка проскакивает мимо.

## Колоды в статике

`npm run decks` копирует `decks/` из корня репозитория в `app/public/decks`.
Скрипт запускается сам перед `dev` и `build`. Копия не коммитится: полтора
мегабайта JSON, дублирующих соседний каталог, только мешали бы читать историю.

## Ответ пишется до перехода

Обязательство из этапа 2 выполнено здесь: `controller.grade()` дожидается
записи в базу и только потом показывает следующую карточку. Закрытая на
анимации вкладка не стоит человеку ответа.

## Чего ещё нет

Дизайна, жестов, анимаций, статистики, звука, экрана настроек и списка колод —
это этапы 4 и 5.
