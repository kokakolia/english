# Collocation SRS — план реализации

## Цель
Сервис интервального повторения для английских коллокаций на карточках.
Главный тренируемый навык — **подобрать правильного партнёра к слову при продукции речи**.
Формат по умолчанию: cloze (пропуск в предложении). В будущем — произвольные колоды.

## Решённое (2026-09-16)
| Вопрос | Решение |
|---|---|
| Клиент | Web PWA: React + TypeScript + Vite, офлайн |
| Источник данных | Парсинг готовых словарей коллокаций (OCD-совместимые) |
| Тип карточек | Cloze — пропуск в контексте |
| Бэкенд | Нет. Офлайн-first, всё локально, бэкап = экспорт файла |

## Принципы
1. **Контент и прогресс — раздельно.** Колода — иммутабельный версионированный файл,
   прогресс — локальная таблица по стабильным `card_id`. Обновление колоды не должно стирать прогресс.
2. **Стабильные ID.** `card_id` = хэш от (лемма коллоката, лемма заголовка, паттерн, тип карточки),
   а не от порядка строк в файле.
3. **Источник данных изолирован.** `pipeline/sources/*` → промежуточный формат → всё остальное.
   Смена источника не затрагивает ни схему колод, ни приложение.
4. **Карточки — производная от коллокации**, генерируются детерминированно. Колоды всегда пересобираемы.
5. **Этап 6 (синк) намеренно последний.** Ранний синк тормозит всё остальное.

## Стек
- Пайплайн: Python 3.11+, spaCy (леммы), pyglossary/readmdict (словарные файлы), pydantic (валидация схемы)
- Приложение: React 18 + TS + Vite, vite-plugin-pwa, Tailwind + Radix, Framer Motion (анимации)
- Хранилище: IndexedDB через Dexie
- SRS: `ts-fsrs` (официальная TS-реализация FSRS) — не писать своё
- Экспорт для проверки: genanki (.apkg)

## Структура репозитория

    English/
      pipeline/          # Python: парсинг → чистка → сборка колод
        sources/         # адаптеры конкретных словарей (изолированы)
        normalize/       # леммы, плейсхолдеры, accept-set
        examples/        # добыча и отбор предложений для cloze
        build/           # сборка колод + валидация + .apkg
        data/            # raw / interim / processed (в git не коммитим)
      schema/            # JSON Schema колоды и карточки + фикстуры
      decks/             # готовые колоды: выход pipeline, вход приложения
      app/               # React PWA

## Модель данных

### Коллокация (промежуточный формат, выход парсера)

    {
      "headword":  { "lemma": "decision", "pos": "noun" },
      "collocate": { "lemma": "make", "pos": "verb" },
      "pattern": "VERB + NOUN",
      "phrase": "make a decision",
      "accept": ["make", "take", "reach", "come to"],
      "register": "neutral",
      "cefr": "A2",
      "freq_rank": 123,
      "source": { "dict": "ocd", "entry": "decision" },
      "examples": [
        { "text": "We need to make a decision by Friday.", "gap": [11, 15], "source": "ocd" }
      ]
    }

### Карточка (выход сборщика, вход приложения)

    {
      "id": "c_9f2a...",
      "type": "cloze",
      "front": "We need to ___ a decision by Friday.",
      "translation": "Нам нужно принять решение до пятницы.",
      "answer": "make",
      "accept": ["make", "take", "reach"],
      "hint": "m___",
      "phrase": "make a decision",
      "pattern": "VERB + NOUN",
      "cefr": "A2",
      "audio": null
    }

### Прогресс (только локально, никогда в файле колоды)
`card_id, state, due, stability, difficulty, reps, lapses, last_review` — поля FSRS.

## Этап 0 — Данные
Самый долгий этап (~40% работы). Артефакт: колода 2000+ карточек, пригодная для ежедневной учёбы.

- [x] 0.1 **Получение источника.** Приоритет — офлайн-словарные файлы (MDX/DSL/StarDict):
      парсятся стабильно, без рейт-лимитов и ломающейся вёрстки. Веб-зеркала (ozdic и подобные) —
      запасной вариант, с задержками и локальным кэшем страниц.
- [x] 0.2 **Парсер → промежуточный формат.** Заголовок → блоки грамматических паттернов
      (ADJ+NOUN, VERB+NOUN, NOUN+VERB, PREP, PHRASES) → коллокаты → примеры.
      Группы синонимов, разделённые вертикальной чертой, разбираются в `accept`.
- [x] 0.3 **Нормализация.** Леммы, артикли, плейсхолдеры `sb/sth`, регистровые пометки,
      дубликаты между записями (одна коллокация встречается в статьях обоих слов).
- [x] 0.4 **Ранжирование.** Частотность заголовочного слова (wordfreq / частотный список),
      CEFR-уровень → порядок изучения и нарезка колод.
      CEFR берём только настоящий, из тренировочных вопросов статей; вывести его из
      частотности нельзя (A2 5.28 / B1 5.16 / B2 5.26 — не различает). Для нарезки
      колод введены полосы сложности, очередь чередуется по заголовочным словам.
- [~] 0.5 **Примеры для cloze — ключевая задача.** Каскад:
      1) пример из словаря, если есть — **сделано**, границы пропуска проставлены;
      2) добыча из открытых корпусов (Tatoeba CC-BY, OpenSubtitles) по точному совпадению фразы;
      3) генерация, если ничего не нашлось.
      Критерии отбора: 6–14 слов, без имён собственных, остальная лексика проще целевой,
      коллокация не в самом начале предложения, контекст однозначно требует именно эту коллокацию.
- [x] 0.6 **Проверка качества пропуска.** Пометить карточки, где пропуск угадывается тривиально
      или, наоборот, не восстановим из контекста. Подсказка (`m___`) как отдельное поле.
      Замер показал, что подсказка не опциональна: без неё у 72% карточек трое и больше
      грамматически подходящих конкурентов, с ней у 55% их нет вовсе.
- [x] 0.7 **Сборка колод.** Срезы по CEFR / частотности / теме. Валидация по JSON Schema,
      нарезка на чанки для ленивой загрузки в PWA.
      Собрана `decks/en-collocations`: 993 карточки, версия = хэш содержимого.
- [x] 0.8 **QA-выгрузка.** Скрипт, дампящий 100 случайных карточек в HTML для ручного просмотра,
      и экспорт `.apkg`, чтобы проверить материал в Anki ещё до готовности приложения.
      Проверка нашла брак 8% и системный дефект: плейсхолдеры `sb`/`sth` затягивали
      в пропуск случайное дополнение. После исправления остаточный брак ~3% —
      неудачные предложения источника, снимаются только LLM-полировкой.

**Готово когда:** 2000+ карточек, ручная проверка 100 случайных, доля брака < 5%.
Сейчас 993 карточки с 78 заголовочных слов — порог берётся дозагрузкой словаря,
пайплайн к ней готов и пересобирает колоду одной командой.

## Риски
| Риск | Митигация |
|---|---|
| Примеров для cloze не хватает на большинство коллокаций | Каскад из этапа 0.5; при нехватке — режим «выбор из вариантов» без предложения |
| Несколько правильных партнёров → ложные ошибки | `accept`-множество в данных с самого начала |
| Обновление колоды стирает прогресс | Стабильные ID + раздельное хранение контента и прогресса (принципы 1–2) |
| Лицензия исходного словаря блокирует публикацию | Слой `sources/` изолирован и заменяем; для личного использования не блокирует |
| Парсер ломается на вёрстке веб-зеркала | Приоритет офлайн-словарным файлам; локальный кэш сырых страниц |
