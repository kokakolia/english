# Работа с проектом

## Проверки перед коммитом

```sh
cd app
npm ci
npm run format
npm run check
npm run build
```

Из корня для изменений пайплайна или контента:

```sh
python -m pip install -r pipeline/requirements-check.txt
python -m pipeline.check
```

GitHub Actions выполняет те же проверки. Разработка использует порт 5174,
рабочая версия с реальным прогрессом — 5173. Изменения схемы проверяйте на
отдельной базе. Не добавляйте личный прогресс, сырьё, зависимости и сборки.

## Границы кода

- `srs` принимает и возвращает данные; не знает о React и IndexedDB.
- `storage` отвечает за транзакции и проверку внешних файлов.
- `study` управляет занятием и отменой, не рендерит интерфейс.
- `ui` отображает состояние и передаёт действия контроллеру.
- Команды в `scripts` не должны требовать сторонних сервисов для обычной сборки.

Поведение, влияющее на расписание, запись данных, копии или публикацию,
проверяйте тестом соответствующего сценария сбоя.

## Изменения контента

Ручные данные находятся в `translations/`, `notes/` и `sentences/`.
Сохраняйте постоянные ID: изменение текста не означает новую карточку.
После изменения партнёров или примера проверьте пояснение и его контекст.
Перед коммитом выполните сборку колоды и проверки пайплайна.

В `decks/` коммитятся манифесты и необходимые части. Старые части, которые
могут читаться клиентами текущей публикации, не удаляются автоматически.
В сборку приложения включаются только части, указанные в текущем манифесте.

## Зависимости

Используйте `npm ci` для установки из lock-файла. Обновляйте зависимости отдельно
с проверкой тестов, сборки и офлайн-запуска. Не применяйте `npm audit fix --force`
без проверки совместимости планировщика и service worker.

Текущее состояние зависимостей — в [docs/maintenance.md](docs/maintenance.md).
