# Источник: ozdic.com

Адаптер этапа 0.1. Задача — сложить сырьё локально, чтобы дальнейшие шаги
(нормализация, отбор примеров, сборка колод) переписывались без походов в сеть.

## Как устроен сайт

Nuxt-SPA с серверным рендерингом. Страницы `/browse/<буква>` наполняются на
клиенте через `/api/`, который закрыт в `robots.txt`, поэтому список слов берём
из sitemap — так, как сайт сам и предполагает.

Ключевая находка: страница `/word/<slug>` отдаёт **полностью структурированные
данные** в теге `<script id="__NUXT_DATA__">`. HTML парсить не нужно вообще.
Формат — devalue: плоский массив, элементы которого ссылаются друг на друга по
индексу; разворачивается в `payload.py`.

## Что лежит в payload

Ключ `data["word-<slug>"]` — словарная статья:

| поле | содержимое |
|---|---|
| `collocations[]` | блоки по частям речи → `groups[] {cat, clusters[]}` |
| `collocations[].groups[].cat` | грамматический паттерн: `ADJ`, `VERB + DECISION`, `PREP`, ... |
| `clusters[].words[]` | **группа взаимозаменяемых партнёров** → наш `accept` |
| `clusters[].example` | готовое предложение с коллокацией (есть примерно у 58% кластеров) |
| `definitions[]` | значения по частям речи |
| `freq` | `{pct, band}` — частотность, вход для ранжирования (этап 0.4) |
| `ipa` | `{uk, us}` |
| `thesaurus`, `related`, `family`, `idioms` | синонимы/антонимы, однокоренные |
| `examples[]` | примеры с указанием источника (Wiktionary, Tatoeba + id) |
| `sources[]` | `wiktionary`, `wordnet`, `tatoeba`, `oxford-collocations` |

Ключи `data["study-bank-<слово>-<часть речи>"]` — готовые тренировочные вопросы,
часть из них типа `fill_in_the_blank_dropdown` с `cefr_level`, вариантами ответа
и объяснением. Сохраняем их тоже: это фактически размеченные cloze-заготовки.

Кластер ложится на модель из `PLAN.md` один в один:

    {"cat": "VERB + DECISION",
     "clusters": [{"words": ["arrive at", "come to", "make", "reach", "take"],
                   "example": "She finally came to a decision about which university..."}]}

→ `phrase` + `accept` + готовый пример для пропуска.

## Использование

```bash
pip install -r pipeline/requirements.txt

python -m pipeline.sources.ozdic.crawl words                      # список слов из sitemap
python -m pipeline.sources.ozdic.crawl run --order freq --limit 15000
python -m pipeline.sources.ozdic.crawl stats
```

`run` продолжается с того места, где остановился: состояние в SQLite, повторный
запуск с теми же флагами до-качивает недостающее. `--retry-failed` повторяет
только страницы с ошибками.

## Раскладка данных (`pipeline/data/raw/ozdic/`, в git не попадает)

    words.txt                       все слаги из sitemap (83 861)
    crawl.sqlite                    состояние обхода, по странице на строку
    entries/<a>/<ab>/<слово>.json.gz статья + study-banks

Шардинг по двум первым буквам: 84k файлов в одной папке NTFS обрабатывает
крайне медленно. Имена файлов проходят через `storage.safe_filename` —
среди английских слов есть `con`, `aux`, `nul`, `prn`, запрещённые в Windows.

## Вежливость

* `/api/`, `/search`, `/me`, `/saved`, `/preview` не трогаем — закрыты в robots.txt;
* частота ограничена глобально (`workers/delay`, по умолчанию 3 запроса в секунду);
* `Retry-After` и коды 429/5xx обрабатываются с экспоненциальной задержкой;
* в User-Agent указан контакт.

## Замеры

| | |
|---|---|
| слов в sitemap | 83 861 |
| страница на проводе | ~100 КБ (brotli), ~450 КБ без сжатия |
| полный обход на 3 rps | ~7.8 ч, ~8 ГБ трафика |
| статей с коллокациями | 295 из 324 на пробном срезе частотных слов |
| кластеров на слово | ~12 |
| кластеров с примером | 58% |

Разжатие brotli обязательно: без пакета `brotli` сервер всё равно пришлёт `br`,
а `requests` вернёт мусор вместо текста. `http.py` объявляет `br` только когда
действительно умеет его читать.

## Лицензия данных

Материал статей восходит к Oxford Collocations Dictionary. Для личного
использования ограничений нет; при публикации сервиса слой источника придётся
заменить — ради этого он и изолирован за промежуточным форматом (принцип 3
в `PLAN.md`), остальной пайплайн о существовании ozdic не знает.
