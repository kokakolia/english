# Отбраковка и сборка колоды (этапы 0.6–0.7)

```bash
python -m pipeline.deck.build run
python -m pipeline.deck.build run --band core --deck-id core-collocations
python -m pipeline.deck.build preview -n 10
python -m pipeline.deck.selftest
```

Выход — каталог `decks/`, который читает приложение. Формат описан в
[`schema/deck.schema.json`](../../schema/deck.schema.json) и проверяется при
каждой сборке: колода, не прошедшая проверку, не записывается.

## Подсказка — часть карточки, а не украшение

Главная проблема cloze для коллокаций — **конкуренты**. У слова `decision`
полтора десятка кластеров прилагательных, и в пропуск «She had to make a ___
decision about the job» грамматически встанет и `tough`, и `important`, и `big`.
Карточка, наказывающая за верный по смыслу ответ, учит неправильному.

Замер по 1186 карточкам-кандидатам:

| | без подсказки | с подсказкой по первой букве |
|---|---|---|
| конкурентов нет | 9% | **55%** |
| один-два | 19% | 30% |
| трое и больше | **72%** | 15% |

Поэтому подсказка считается вместе с карточкой, а `ambiguity` меряет конкурентов
уже с её учётом. Конкурентами считаются партнёры других кластеров того же слова,
в том же грамматическом отношении и том же значении — то есть те, что встали бы
в этот же пропуск.

## Что отбраковывается

| причина | карточек | почему |
|---|---|---|
| `ambiguous` | 146 | трое и больше конкурентов даже с подсказкой |
| `gap_too_large` | 15 | пропуск длиннее трёх слов и больше трети предложения — контекста не остаётся |
| `gap_at_start` | 14 | ответ с заглавной буквы и без левого контекста |
| `answer_repeated` | 3 | ответ встречается в этом же предложении, его можно списать |

Пометки `sentence_long` и `proper_noun` карточку не отбраковывают: они
сохраняются в поле `flags`, чтобы приложение могло отфильтровать их само.
Исходный план требовал убирать имена собственные, но `Sarah` в предложении не
мешает восстановить пропуск, а материала стоит заметно.

## Формат

Колода лежит в `decks/<id>/`: метаданные в `deck.json`, карточки в
`cards-000.json` и далее по 250 штук. Разбиение на части — ради ленивой загрузки
в приложении.

`version` — хэш содержимого, а не дата сборки: он меняется только когда
изменились сами карточки, и приложение по нему понимает, нужно ли обновляться.
Пересборка без изменений в данных даёт ту же версию. В хэш входит и перевод —
иначе исправленный перевод не доехал бы до приложения.

**Перевод — на лицевой стороне.** Поле `translation` показывается вместе с
пропуском, а не после ответа: оно задаёт смысл, который нужно выразить
по-английски. Без него карточка «My grandmother ___ her great-grandchildren
graduate» допускает десяток осмысленных вариантов, и угадывать приходится не
смысл, а замысел словаря. Подробности — в [README переводов](../translate/README.md).

**На обороте — заметка, а не разметка.** Поле `note` объясняет, как коллокация
употребляется и чем различаются варианты внутри кластера; грамматический тип и
полоса сложности остались в данных и в тегах Anki, но с карточки убраны.
Поле `also` перечисляет остальных партнёров кластера, кроме того, что уже стоит
в предложении, и пусто, когда партнёр один. Подробности — в
[README заметок](../usage/README.md).

**`answer` и `accept` — разные вещи.** `answer` — точная форма, стоявшая в
предложении (`demonstrated`), `accept` — словарные формы всех партнёров кластера
(`demonstrate, prove, show, suggest`). Проверять ввод нужно по леммам: все
партнёры кластера взаимозаменяемы, и наказывать за любой из них нельзя. Эта
логика — в ядре SRS на этапе 1.

## Выгрузка наружу (этап 0.8)

```bash
python -m pipeline.deck.export anki          # .apkg для Anki
python -m pipeline.deck.export html -n 100   # страница для ручного просмотра
```

Обе выгрузки идут из `decks/`, а не из базы: проверять надо ровно то, что
получит приложение. Файлы пишутся в `pipeline/data/export/` и в git не попадают.

Заметки Anki получают `guid` из нашего `card.id`, поэтому повторный импорт
обновляет те же заметки, а не насыпает дубли поверх выученного. Теги
(`rel::verb_obj`, `band::core`, `cefr::A2`, `amb::low`) позволяют отбирать
подмножества прямо в Anki.

## Результат ручной проверки

Сто случайных карточек прочитаны глазами. Брак — **8 из 100** при плановом
пороге в 5%, и пять из восьми оказались одним и тем же дефектом:

```
He didn't want to ___ show during the job interview.   ↳ «let his nervousness»
After the party ended late, Tom ___ through the streets. ↳ «saw his elderly neighbor home»
```

Записи `let sth`, `hear sb`, `keep sth`, `see sb home`, `give sb/sth` содержат
плейсхолдер, и то, что он поймал в предложении, уезжало в пропуск вместе с
партнёром. Произвести «his elderly neighbor» учащийся не может — это не
коллокация, а случайное дополнение.

Исправлено в `normalize/build.py`: в пропуск попадает только то, что учащийся
способен произвести, — сам партнёр. Заголовочное слово и содержимое
плейсхолдеров остаются видимыми как опора. Те же карточки теперь выглядят так:

```
He didn't want to ___ his nervousness show during the job interview.   ↳ «let»
After the party ended late, Tom ___ his elderly neighbor home ...      ↳ «saw»
```

Побочный эффект: пропуски стали короче, по размеру отсеивается вдвое меньше
записей, и колода выросла с 993 до 1008 карточек.

Оставшиеся три дефекта из ста автоматически не ловятся — это неудачные
предложения самого источника: «Can you wait in a second while I grab my coat»
(так по-английски не говорят), «has become world beaters» (нужно единственное
число). Порядка 3% — это остаточный уровень, который снимается только проверкой
примеров на этапе LLM-полировки.

## Известные ограничения

* **Предлогов четверть колоды** (247 из 1008) несмотря на штраф в ранжировании:
  у предложных записей чаще всего находится готовый пример, и они проходят
  отбор. Это скорее грамматика, чем коллокации.
* **Конкуренты считаются только внутри одного значения.** Если словарь не делит
  статью на значения, кластеры разных смыслов попадут в одну группу, и
  неоднозначность будет завышена.
* **Отбраковка синтаксическая.** Она ловит «ответ виден в предложении» и
  «контекста не осталось», но не ловит «предложение само по себе неудачное» —
  именно этот класс и составил остаточные 3% брака. Нужна проверка примеров
  языковой моделью.
