# Заметки об употреблении

```bash
python -m pipeline.usage.build stats
python -m pipeline.usage.build todo --batch 200 --out батч.tsv
python -m pipeline.usage.build load батч-готово.tsv
python -m pipeline.usage.build show -n 5
```

## Что стоит на обороте карточки

Раньше там была строка вида `go on to state · verb+obj · core · уровень не
размечен · неоднозначность low`. Учащемуся она не нужна: грамматический тип и
полоса сложности — это разметка для пайплайна и фильтров, а не знание о языке.
Теперь на её месте заметка о том, **как эта коллокация употребляется**:

```
come in + упаковка, размер или цвет — о том, в каком виде продаётся товар:
comes in a can, comes in three sizes, comes in blue. Значение «приходить»
здесь ни при чём.
```

Разметка никуда не делась — она осталась в данных колоды и в тегах Anki
(`rel::verb_obj`, `band::core`, `cefr::A2`), так что отбирать подмножества
по-прежнему можно.

## Что в заметке

Одно-два предложения: схема употребления, смысл, типичные примеры и
предостережение от ошибки там, где она вероятна. Отдельная задача заметки —
объяснить **разницу внутри кластера**, которую карточка иначе скрывает: она
принимает и `make`, и `take`, и `reach a decision`, но это не значит, что они
равнозначны.

## Ещё варианты

Строка под заметкой показывает **остальных** партнёров кластера, без того, что
уже стоит в предложении: повторять только что названный ответ бессмысленно.
Если партнёр в кластере один, строки нет вовсе — сейчас так у 705 карточек
из 1008.

## Где лежат

`notes/usage-ru.tsv` в репозитории: идентификатор коллокации, подпись, текст и хэш контекста,
отсортировано по подписи. Как и переводы, заметки написаны руками и повторным
запуском не восстанавливаются, поэтому им не место в `pipeline/data/`.

Ключ — постоянный `card.id` из `schema/card-identities.json`. Набор партнёров
может меняться без потери прогресса. Четвёртая колонка TSV хранит хэш контекста:
партнёры, предложение с пропуском и ответ. При изменении контекста заметка
не используется, пока её не проверят и повторно не загрузят через `load`.

`todo` передаёт хэш контекста второй колонкой после ID. Ответ автора должен
содержать три колонки: `<id> <TAB> <хэш из задания> <TAB> <заметка>`. `load`
сверяет этот хэш с текущей карточкой и сохраняет именно подтверждённый токен.
Старый ответ после смены примера, двухколоночный ответ без хэша или повторный ID
отменяют весь импорт без изменений файла заметок. Нужно заново выгрузить `todo`
и проверить текст для актуального контекста.

Строка «другие сочетания с этим словом» перечисляет словарных партнёров,
а не готовые замены пропуска. Значение и грамматическая форма зависят от контекста.

`prune` проверяет ID во всех опубликованных колодах, даже если `--deck-id`
указывает на подколоду. Общий TSV теряет только записи, отсутствующие во всём
каталоге. Перед изменением файла проверяются манифесты, число карточек и
контрольные суммы новых публикаций. Неполный каталог отменяет очистку.
