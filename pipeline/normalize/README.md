# Нормализация (этап 0.2)

Превращает скачанные словарные статьи в промежуточный формат коллокаций —
границу, выше которой пайплайн ничего не знает про ozdic.

```bash
python -m pipeline.normalize.build run        # разобрать новое
python -m pipeline.normalize.build stats      # сводка
python -m pipeline.normalize.build sample --cloze-only -n 10
python -m pipeline.normalize.selftest         # проверки правил разбора
```

## Рассчитано на дозагрузку

Обход словаря будет идти порциями, поэтому нормализатор инкрементальный:

- таблица `state` помнит для каждой статьи, когда она скачана и какой версией
  правил разобрана. Повторный `run` трогает только новое — разобранное не
  пересчитывается;
- правила разбора версионированы (`build.VERSION`). Подняли версию — следующий
  `run` сам пересоберёт всё, вручную ничего чистить не нужно;
- запись статьи заменяется целиком (`replace_slug`), а не дописывается: если
  после правки правил часть записей исчезла, сирот в базе не останется;
- `forget_missing` убирает статьи, пропавшие из сырья;
- идентификатор коллокации стабилен и **не зависит от примера**: замена
  предложения не создаёт новую карточку и не обнуляет прогресс.

То есть после «докачать ещё 5000 слов» достаточно повторить `run`.

## Что делает разбор

| шаг              | модуль        | суть                                                           |
| ---------------- | ------------- | -------------------------------------------------------------- |
| паттерн          | `patterns.py` | `VERB + DECISION` → отношение `verb+obj` + позиция партнёра    |
| раскрытие записи | `variants.py` | `(very) much` → «very much», «much»; `in (a/the)~` → три формы |
| поиск в примере  | `inflect.py`  | границы партнёра в предложении с учётом словоформ              |
| сборка           | `build.py`    | обход статей, запись в базу                                    |

Типы отношений: `adj+noun`, `verb+obj`, `noun+verb`, `noun+noun`, `adv+verb`,
`adv+adj`, `verb+adj`, `quant+noun`, `prep`, `phrase`.

### Почему не spaCy

Для пропуска нужны точные границы партнёра в примере, а пример почти всегда
содержит не словарную форму: `get better` → «My English has **gotten** better».
Но задача здесь не «разобрать текст», а «найти конкретное слово», поэтому вместо
парсера — порождение правдоподобных словоформ и поиск по ним. Перегенерация
форм безвредна: мы ищем их в тексте, а не показываем пользователю.

Коллокация ищется целиком, одной регуляркой с группой на месте пропуска. Иначе
в предложении «My sister is best at cooking» предлог `at` из пары `at best`
найдётся в любом другом месте.

## Известные ограничения

- **Слэш в многословной записи.** В `a/the` он делит одно слово, а в
  `ahead of/behind ~` — кусок из двух. Автоматически не различить, такие записи
  помечены `needs_review` и ждут этапа 0.8.
- **Конструкции с `of`.** `NOUN + CAN` означает «can of food», а собирается как
  «food can». Пропуск в таких записях не ставится — в карточки они не попадут.
- **Артикль внутри пропуска.** `after a/the ~` даёт ответ «after a», а не
  «after». Для устойчивых выражений («after a while») это верно, для остальных
  спорно.
- **Открытые классы.** `300g/250ml/11oz can`, `7-hour/8-hour day` — партнёр там
  любой подходящий, готовой карточкой они не становятся.
- **Подпись коллокации не является учебным материалом.** Артикли в ней не
  расставляются; правильная английская фраза берётся из примера.

## Постоянные идентификаторы

`schema/card-identities.json` хранит выпущенные ID, известные наборы партнёров
и область значения: источник, слово, часть речи, отношение, смысл. Все 1008
существующих ID сохранены. Добавление, удаление и перестановка партнёров
продолжают прежний кластер; реестр сохраняется при `run` и коммитится с данными.

Неоднозначное слияние или разделение кластеров останавливает нормализацию.
Проверьте изменения источника и явно назначьте разные ID/алиасы в реестре.
Не удаляйте старые записи: на них могут ссылаться прогресс и резервные копии.
Полная замена значения без общих партнёров создаёт новую карточку.
