# Переводы предложений

```bash
python -m pipeline.translate.build stats
python -m pipeline.translate.build todo --batch 200 --out батч.tsv
python -m pipeline.translate.build load батч-готово.tsv
python -m pipeline.translate.build prune
```

## Зачем перевод на карточке

Перевод стоит на **лицевой** стороне, вместе с пропуском. Это не подсказка,
которую жалко показать, — это условие задачи.

Без перевода карточка «My grandmother ___ her great-grandchildren graduate»
допускает десяток осмысленных вариантов, и угадать нужно не смысл, а то, какую
именно коллокацию имел в виду словарь. С переводом «Моя бабушка дожила до того,
как её правнуки окончили университет» задача становится той самой, ради которой
всё затевалось: смысл известен, нужно выдать английскую коллокацию.

Это же снимает главную измеренную проблему cloze: без подсказки у 72% карточек
было три и более грамматически подходящих конкурента (см. README сборщика
колоды). Перевод отсекает их по смыслу, а не по первой букве.

## Где они лежат

`translations/en-ru.tsv` — **в репозитории**, три колонки: ключ, английский,
русский, отсортировано по английскому предложению.

Это сознательно не база в `pipeline/data/`: скачанное сырьё восстанавливается
повторным обходом, а переводы сделаны руками и не восстанавливаются никак. В
текстовом файле их к тому же видно в diff построчно, и правки можно
просматривать как код.

## Перевод привязан к предложению, а не к карточке

Ключ — хэш текста предложения. Это важно в обе стороны:

* набор партнёров в кластере может измениться, идентификатор карточки вместе с
  ним — а предложение останется прежним, и переводить его заново не придётся;
* если пример заменили, перевод старого предложения к новому не подходит и
  просто перестаёт использоваться (а `prune` его уберёт).

Переводы стоят дорого, поэтому таблица живёт отдельно от колоды и переживает
любые её пересборки.

## Обмен по коротким ключам

`todo` выдаёт строки `<ключ> <TAB> <предложение>`, обратно достаточно прислать
`<ключ> <TAB> <перевод>` — переписывать английский текст второй раз не нужно.
Ключ это первые восемь знаков хэша, и соответствие восстанавливается из самой
колоды, поэтому между запусками не нужно хранить никакого состояния. Пара
`<предложение> <TAB> <перевод>` тоже принимается.

## Текущее состояние

Все 1008 предложений колоды переведены вручную (не машинным переводчиком):
перевод должен однозначно показывать смысл **целевой** коллокации — «дожить до»,
а не просто «прожить», — а для этого нужно знать, какая коллокация в карточке
целевая.

Версия колоды считается с учётом перевода: исправленный перевод меняет версию,
и приложение понимает, что нужно обновиться.
